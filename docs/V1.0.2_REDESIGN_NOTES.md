# v1.0.2 implementation and redesign notes

This file records decisions made while applying the technical handoff package. It is a status note, not an executable instruction set.

## Implemented

- Parser inputs are bounded before and after normalization, multi-expression evaluation is bounded, and exact intermediate values are checked after every arithmetic binary operation.
- Exact rational bases and negative integer powers are preflighted before constructing an oversized numerator or denominator.
- Real definite integrals now accept explicit infinity aliases and support convergent improper endpoints. Known interior singularities are split into one-sided pieces, so an ordinary integral cannot silently become a Cauchy principal value.
- Complex definite and parameterized contour integrals are explicit Complex-mode operations. Contours use a finite real parameter interval and reject a path crossing a detected pole.
- Application close has a bounded synchronous worker-reaping path; ordinary cancellation remains non-blocking for the running UI.
- Calculus policy, calculator domain errors, and finite-number checks are now focused modules. They are imported without a circular module dependency; `ScientificCalculatorEngine` remains the stable public facade.
- A cancelled controller worker can safely find its result pipe closed, preventing a normal cancellation from becoming a noisy child-process traceback.
- Linux CI requires the live Tk suite through Xvfb. Dependency lists are checked against `pyproject.toml`.

## Deliberate redesigns and boundaries

- A behavior-preserving complete rewrite of the Tk presentation layer is not appropriate for a patch release. The calculation layer received focused, behavior-preserving extraction; further UI extraction should be an independently reviewed minor-version project.
- The release criterion is real branch coverage, not a synthetic percentage. Platform rendering, packaging, and defensive operating-system error paths are expanded only when a deterministic behavioral test can exercise them. No coverage exclusions are used.
- The old postfix-percent implementation remains under the raw 2,048-character ceiling. Replacing it with a new tokenizer would be a parser-semantics change, so it is deferred rather than risk changing calculator precedence in a patch release.
- Windows code signing, macOS notarization, and manual Windows/Linux/macOS device acceptance tests require external certificates or devices. The release workflow states those limits explicitly and must not claim those checks passed without the required external evidence.
